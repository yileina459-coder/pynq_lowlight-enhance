# skill — 可复用 PYNQ 技能包

赛规要求：`skill/` 里的每一项都要写清 **适用范围 / 使用方法 / 失效条件 / 已验证效果**，
并且要"不与本队题目绑定 —— 换一个题目、换一块板卡仍然可用"。面向 PYNQ 且满足这个条件的
Skill 单独加分。

## 现有内容

| Skill | 状态 | 一句话 |
| --- | --- | --- |
| [`golden_compare/`](golden_compare/README.md) | 已验证 | 硬件输出与黄金参考的逐位比对，报出第一个不一致像素的坐标 |
| [`perf_collect/`](perf_collect/README.md) | 已验证 | 测量数据统一入库（CSV）并生成报告用的 markdown 表 |
| `overlay_check/` | 计划中 | Overlay 加载与校验流程：IP 清单、地址映射、时钟、DMA 通道自检 |
| `dma_stream/` | 计划中 | DMA 搬运与缓存一致性封装，含按行流式传输与超时定位 |

后两个要等 DMA 版 overlay 上板跑通之后再写 —— 那时的"已验证效果"才有真实数据，
而不是先写文档再补证据。

## 这些 Skill 从哪来

不是凭空设计的，都是从本项目实际踩的坑里提炼的：

- `golden_compare`：Sobel 核的边界策略（水平复制、垂直用上一帧的行）如果不写死，
  硬件和软件参考就会"看着差不多但对不上"。所以比对工具必须默认 0 容差、必须报坐标。
- `perf_collect`：报告里的性能数字必须能追溯到某次运行的原始日志，否则 20 分那项
  经不起复核。

## 使用约定

- 每个 Skill 都是**独立目录 + 一个可直接运行的脚本**，不依赖本仓库其它代码；
- 依赖只用 `numpy` + `Pillow`（PYNQ 镜像自带），不引入需要联网安装的包；
- 退出码 0/非 0 表示通过/失败，方便直接串进脚本或 CI。
