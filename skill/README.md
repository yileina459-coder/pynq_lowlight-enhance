# skill — 可复用 PYNQ 技能包

这里的每一项都是独立可用的工具，面向 PYNQ 框架，**不绑定本仓库的题目**：换一个题目、
换一块板卡仍然可以用。每一项都写清 **适用范围 / 使用方法 / 失效条件 / 已验证效果**。

| Skill | 类型 | 做什么 | 已验证效果 |
| --- | --- | --- | --- |
| [`overlay_check/`](overlay_check/README.md) | 校验脚本 | Overlay 上板前离线校验：IP 清单、寄存器地址、时钟频率、bit 与 hwh 是否配对 | 在本项目 4 个 overlay 上拦下过 3 次 bit/hwh 不配对与 1 次时钟频率写错 |
| [`golden_compare/`](golden_compare/README.md) | 校验脚本 | 硬件输出与黄金参考逐位比对，报出第一个不一致像素的坐标 | 8 档预设 1280×720 全帧比对，差异 0 / 2,764,800 |
| [`perf_collect/`](perf_collect/README.md) | 校验脚本 | 测量数据统一入库（CSV）并生成 markdown 对比表 | 板上 300 帧计时与 Python 参考的耗时表都由它生成 |
| [`dma_stream/`](dma_stream/README.md) | 案例模板 | AXI-DMA 搬运与缓存一致性封装，带超时定位 | 640×480 与 1280×720 两条通路的搬运都跑通，超时定位救过两次"没反应" |
| [`pitfalls/`](pitfalls/README.md) | 踩坑清单 | 结构化整理的常见错误、触发条件与排查步骤 | 列出的 7 类问题在本项目里都实际发生过，并给出了定位方法 |

## 为什么不绑题目

- 不依赖本项目的 overlay 名字、算子或数据格式：`find_dma()` 兼容 `pynq.lib.dma.DMA` 与
  `DefaultIP` 两种实例，`golden_compare` 只要求两边是同样形状的数组；
- 换板卡时只需要改 IP 名与寄存器地址，处理流程一行不用改；
- 只用 `numpy` + `Pillow`（PYNQ 镜像自带），不引入需要联网安装的包。

## 这些 Skill 从哪来

不是凭空设计的，都是从本项目实际踩的坑里提炼的：

- `golden_compare`：Sobel 核的边界策略（水平复制、垂直用上一帧的行）如果不写死，
  硬件和软件参考就会"看着差不多但对不上"。所以比对工具必须默认 0 容差、必须报坐标。
  边界策略最终固定为这两种，才拿到 0 / 2,764,800 的结果。
- `dma_stream`：PYNQ 的 DMA 实例类型在不同版本里不一致，缓存没 flush/invalidate 时
  现象与"算法写错"完全一样，靠这两条才把问题分开。
- `perf_collect`：报告里的性能数字必须能追溯到某次运行的原始日志，否则复核时对不上。
- `overlay_check`：bit 与 hwh 版本不一致时，板子不报错，只是结果全错——所以上板前先离线校验。
- `pitfalls`：把上面这些失败按"现象 → 触发条件 → 排查步骤"整理成清单。

## 使用约定

- 每个 Skill 都是**独立目录 + 一个可直接运行的脚本**，不依赖本仓库其它代码；
- 退出码 0/非 0 表示通过/失败，方便直接串进脚本或 CI；
- 命令行参数、输入输出格式都写在各自的 README 里，照抄即可运行。
