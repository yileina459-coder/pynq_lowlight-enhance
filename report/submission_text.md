```
面向低照度图像观察的低延迟视觉增强终端，基于 PYNQ-Z2（XC7Z020）与 Vitis HLS 2026.1。作品不经过帧缓冲：局部对比 → 双段色调曲线 → 二值/反色/单色 → 分屏对比，整条增强链在一颗 AXI-Stream 流式内核中逐像素完成，片上实测流水线延迟 16 个像素时钟（160 ns）。59 bit 参数与 10 档场景预设由 PS 运行时下发，切换不复位、不中断画面。全整数定点实现，可与 numpy 黄金模型做 0 容差比对：AXI-DMA 整帧回环下 8 个预设各 0/2764800 通道不一致，720p 整帧 15.6 ms（63 fps）；同一内核在 HDMI 通路上以 640×480@60 持续出图。算子族另含 Sobel、高斯、锐化，同一算法 PS 纯软件 3108.4 ms/帧、PL 15.8 ms/帧，加速 196.7 倍（II=1，LUT 占用 3%）。帧源为 PS 预载的图像/视频帧，摄像头直通受本板 HDMI 模式限制尚未打通。
```

## 五、作品简介 · 详细版（1061 字符 / 552 汉字，超上限，留给展板、报告摘要、答辩材料）

```
低照度条件下的图像观察（夜间巡检、暗光取证、车载夜视、工业与显微成像）真正的瓶颈往往不是帧率，而是延迟：通用手机或 PC 方案从采集到显示通常有 100~300 ms，移动观察时画面迟滞、拖影，长时间使用容易疲劳。

本作品在 PYNQ-Z2（Zynq-7000 XC7Z020）上把整条增强链放进像素流里，而不是放在帧缓冲之后：局部对比增强 → 双段色调曲线（独立拐点与双段增益）→ 二值化/反色/单色 → 左右分屏对比，全部由一颗 AXI-Stream 流式内核逐像素完成，不读写 DDR、不需要整帧缓存，像素进多少出多少。片上双时间戳实测流水线延迟 16 个像素时钟（160 ns），相当于 720p60 一行视频时间（17.2 µs）的 1%，把处理延迟从「一帧」压到「一行的百分之一」。

核心算子 enhance 由 Vitis HLS 2026.1 实现：II=1，BRAM 3 / DSP 2 / FF 2168 / LUT 1659（占 XC7Z020 的 3%），7 ns 约束下估计 Fmax 194.59 MHz，高于视频通路的 142.86 MHz。59 bit 参数（清晰度、拐点、双段增益、二值阈值、反色/单色、分屏位置）由 PS 经 AXI 在运行时下发，内置 10 档场景预设（pass / clarity / crisp / bright / night / document / reading / invert / binarize / split），切换不复位、不中断像素流——实测 150 s 内 25 次切换、741 次写帧，0 次卡顿。

为回答「结果对不对」，全链采用整数定点实现，并配有独立编写的 numpy 黄金模型：AXI-DMA 整帧回环比对下，8 个预设各 0/2764800 通道不一致（逐位一致），720p 整帧 15.6 ms（63 fps）；同一个内核又在 HDMI 通路上以 640×480@60 持续出图（WNS +0.206 ns，切预设无黑屏），既能被数字验证，也能被肉眼检验。算子族另含 Sobel、高斯、锐化三个流式卷积核：以 Sobel 为例，同一算法 PS 纯软件 3108.4 ms/帧，PL 15.8 ms/帧，加速 196.7 倍，帧率 0.32 → 63.45 fps。

**当前的边界**：帧源是 PS 预载的图像与视频帧，经 VDMA 持续送进像素通路。这块板子的 HDMI 输出实测只支持 640×480，而 HDMI 输入 IP 无法工作在 640×480，因此「摄像头 → 板子 → 显示器」的直通链路没有打通，作品交付的形态是内核位于真实像素流中、由 VDMA 供帧、板上 60 Hz 持续输出。构建全流程（HLS 工程、块设计、位流、上板测试、图片与视频上传演示）均已脚本化，可从零一条命令重建。
```

## 七、填写注意

1. **不要再写「实时」**。真正意义上的实时是「摄像头进 → 屏幕出、无需人工灌帧」，这条直通链路**没打通**（本板 HDMI 输出只支持 640×480，HDMI 输入 IP 不支持该模式，见 `docs/hdmi_status.md`）。可以写的事实只有三条：内核在真实像素流上工作、HDMI 通路 640×480@60 持续输出、DMA 通路 720p 整帧 15.6 ms（63 fps，吞吐高于 720p60 所需的 16.7 ms）。写「实时」等于把没做的事算成做了。
2. **延迟怎么表述**：写「片上流水线延迟 16 个像素时钟 = 160 ns」（HDMI 通路 21 拍 = 147 ns，两个数都对，别混用），不要说「端到端 160 ns」——端到端没测，也没打通。
3. **对比倍数归属**：196.7× 是 **Sobel** 的 PS vs PL 数据（`report/comparison.md`），不要写成 enhance 的加速比；enhance 自己的板上数据是 15.6 ms/帧 + 逐位一致。
4. **8 个还是 10 个预设**：板上逐位比对做过的是 8 个预设（各 0/2764800 通道），参数表现有 10 档。写「10 档预设可切换」和「8 个预设逐位比对通过」都成立，别混成「10 个预设逐位一致」。两点补充：那 8 档是 DMA 验证用的**旧参数表**（`night`/`document` 与当前 10 档表不同）；Jupyter 面板也还是那 8 档，常驻/上传路径才是 10 档。
5. **不要写功耗**：PYNQ-Z2 无板载功率计，功耗一栏至今空着，任何功耗数字都是编的。
6. **HDMI 只能 640×480** 是这块板子的实测上限（原厂位流同样如此），不要写 720p / 1080p 输出；DMA 通路的 15.6 ms 是 720p，但那是回环进 DDR 的批处理通路，不是 HDMI 输出分辨率。
7. **字数口径**：上表按「字符数（不含空格，含标点与英文数字）」统计，均远低于 500。
