# 采购与接线清单（2026-10-19）

目标：在没有显示器、没有 HDMI 源的条件下，让 PYNQ-Z2 的处理结果**能被看到、被录下来**，并且能测功耗。

预算上限 200 元。**只买「必买」三项，其余按条件。**

## 已确认（2026-10-19，队员核对实物）

| 事实 | 影响 |
|---|---|
| 笔记本有 **1 个 HDMI 口** | **不用买 USB-C→HDMI 转接**；一个口够用：它当信号源，回来的画面走 USB 采集卡 |
| 板子有 **DC IN** | 供电走 12 V 圆孔，**功率计要买直流在线款**（不是 USB 款） |
| 板子有 HDMI IN / HDMI OUT / USB HOST / LINE IN / HP+MIC | HDMI 两端口齐全，音视频口本次不用 |
| 板子有 **Ethernet** 与 **PROG-UART（micro USB）** | Jupyter 走网口；串口可看启动日志。清单无需再改 |

| # | 物品 | 关键规格 | 价格 |

> 若暂时不想折腾，**先不买**，报告里把功耗标为「未测」——不影响校赛和初赛材料。


### 不要买（都是坑）

| 别买 | 原因 |
|---|---|
| HDMI 显示器 | 采集卡已经承担「显示 + 录像」两件事，省 300~800 元 |
| USB 摄像头 | PYNQ-Z2 的 USB Host 接 UVC 摄像头在社区里长期不稳，别在 16 天里踩这个坑 |
| HDMI 分配器 / 切换器 | 多一个故障点；采集卡本身就能当唯一 sink |
| HDMI EDID 模拟器 | **不需要**：你们的 overlay 里 `dvi2rgb` 已经加载了 `720p_edid.data`，板子会主动向笔记本报告「我是 1280×720 显示器」 |

## 二、连接图

```
┌──────────┐   HDMI 线 A（1.5~2 m）    ┌─────────────────────────┐
│  笔记本   │ ────────────────────────► │ HDMI IN     PYNQ-Z2     │
│ (信号源)  │                           │                         │
│           │   HDMI 线 B（0.5 m）      │ HDMI OUT                │
│           │ ◄──────────────────────── │                         │
│  采集卡   │                           │ DC IN (12 V) ◄─ 电源适配器 │
│   (USB)   │ ─── USB-A ──► 笔记本 USB3 │ Ethernet ──► 路由器/直连 │
└──────────┘                           │ 电源开关 → ON            │
                                       └─────────────────────────┘
```

信号方向一句话：**笔记本 → 板子 HDMI IN → 板内流水线 → 板子 HDMI OUT → 采集卡 → 笔记本 USB**。

板上的位置（按丝印找，不用拆包装）：

| 板上丝印 | 位置 | 接什么 |
|---|---|---|
| `HDMI IN` | 板边，Type-A 母口 | 线 A，来自笔记本 |
| `HDMI OUT` | 板边，Type-A 母口 | 线 B，去采集卡 |
| `PROG - UART` | micro USB 口 | 到笔记本，看启动日志（可选；Jupyter 能替代） |
| `Ethernet` / `RJ45` | 板边 | 网线到路由器（或直连笔记本），**必需** |
| `DC IN` | 板边，5.5 mm 圆孔 | 12 V 适配器（保持现状，别换型号） |
| 电源开关 | 板边 | ON/OFF |
| Micro SD | **板子背面**卡槽 | 已烧好 PYNQ 镜像 |

## 三、验收顺序（严格按这个次序，出问题时能立刻定位到哪一段）

**第 1 步 · 只验采集卡（不接板子）**

1. 笔记本 HDMI → 采集卡 HDMI IN，采集卡 USB 插笔记本 **USB 3.0（蓝色）口**
2. Windows 打开「相机」App 或 OBS Studio，添加「视频采集设备」
3. 期望：看到笔记本桌面镜像，分辨率 1920×1080 或 1280×720

> 这步失败 → 问题在采集卡/线 A/USB 口，与板子无关。

**第 2 步 · 板子单独起来（不接 HDMI）**

1. 网线接板子与路由器，SD 卡插好，**DC IN 接 12 V 适配器**，开关打到 ON
2. 期望：红灯亮 → 几秒后黄色 Done 灯亮 → 一分钟后蓝灯闪
3. 浏览器打开 `http://pynq:9090`（DHCP）或 `http://192.168.2.99:9090`（直连静态 IP）

> 这步失败 → 与本次采购无关，是供电/镜像/网络问题。

**第 3 步 · 接上 HDMI，看 Windows 认不认这块屏**

1. 线 A 从采集卡挪到板子 `HDMI IN`；线 B 从板子 `HDMI OUT` 到采集卡
2. 笔记本：`Win + P` → 选「**扩展**」；设置 → 显示 → 选中那块新屏 → 分辨率 **1280×720**、刷新率 **60 Hz**
3. 期望：Windows 显示里出现一块 **1280×720** 的显示器（这是板子通过 `720p_edid.data` 报告的）

> 第 3 步看到 1280×720 就说明 HDMI IN 的 DDC/EDID 通了，这是整条链最容易被卡住的一环。

**第 4 步 · 跑 overlay，看输出**

```bash
# 板上，目录里放 sobel_hdmi.bit / sobel_hdmi.hwh / hdmi_sobel.py
python3 hdmi_sobel.py --seconds 10
```

期望终端输出：

```text
detected input mode: 1280x720 @ 60.00 Hz, pixel clock 74.25 MHz
pipeline running - HDMI OUT should now show the Sobel edge image
RESULT: OK
```

同时 OBS 预览里应该出现边缘图。

**第 5 步 · 录下来**

OBS 里「开始录制」，录 10 秒，确认文件能播——这就是后面 5 分钟演示视频的素材来源。

## 四、笔记本侧设置要点

| 项 | 设置 | 为什么 |
|---|---|---|
| 显示模式 | **扩展**（不是复制） | 复制模式会被笔记本内屏 1080p 拉回去 |
| 分辨率 | 1280×720 @ 60 Hz | PYNQ-Z2 前端只保证到 720p；你的流水线时钟 142.86 MHz、一像素一拍，1080p60 的 148.5 Mpixel/s 带不动 |
| HDR / 缩放 | 关闭 HDR，缩放 100% | HDR 会改变像素编码；缩放会让 Windows 用非原生分辨率 |
| 采集卡格式 | OBS 里选 **MJPEG 或 YUY2**、1280×720、60 fps | 未压缩 720p60 走 USB2 会带宽不足 |

## 五、常见故障对照

| 现象 | 最可能原因 | 处理 |
|---|---|---|
| 采集卡完全没画面 | 插在 USB 2.0 口 / 线 A 坏 / 采集卡驱动未加载 | 换 USB 3.0 口；换线；设备管理器看有没有「USB Video Device」 |
| Windows 只显示 1024×768 或没有第二块屏 | 板子没上电 / overlay 没加载 / dvi2rgb 没起来 | 先确认第 2 步；EDID 由 PL 提供，overlay 不加载就没有 EDID |
| 有画面但花屏/闪 | 线太长、接触不良、像素时钟未锁 | 换短线；重新插拔；看终端有没有 `no HDMI input signal detected` |
| 终端报 `no HDMI input signal detected` | 笔记本没在输出（休眠/未扩展） | `Win + P` 重新切扩展；动一下鼠标 |
| 采集卡预览正常但板上报错 | 板子 HDMI OUT 没配置成功 | 确认脚本里 `hdmi_out.configure(hdmi_in.mode)` 在 `hdmi_in.configure()` 之后 |
| 画面比例不对/颜色异常 | 像素格式不匹配（RGB vs YUV） | 检查 `hdmi_in.configure()` 的 `pixelformat`，改成 RGB |
